# 本地交付复核

2026-10-01。本次围绕消费者的持续使用、操作失败语义和复现材料收敛，不扩充协议支持范围、不创建远端或发布。最初未安装 broker；用户随后明确批准本地测试，已运行官方校验过的 Artemis 2.57.0 并记录真实互操作。

| 缺陷 | 修复后的行为 | 有效验证 |
| --- | --- | --- |
| UNSUBSCRIBE 留有待确认消息时立即复用 ID，会让不同订阅代际共享累计 ACK 的分组 | 旧消息未结清前拒绝复用该 ID，保持会话和旧确认状态；结清后允许新订阅选择不同 ACK 模式 | 旧累计模式两条 → 退订 → 新个别模式同 ID 被拒绝 → 确认旧两条 → 重订阅成功 → 新模式确认第二条仍保留第一条。 |
| TCP `receipt()` 等待者已满，仍可能把命令写入 socket | 在注册/发送前拒绝容量和参数错误，保留健康连接 | 真实回环会话占满等待槽；拒绝 receipt、重复 receipt header 与无效参数，断言 write 调用数为 0；随后连接仍可正常使用。 |
| 使用同 ID 的队列旧回执会立即满足新请求的等待者 | 旧回执未消费时拒绝复用，不发送；先消费旧回执后可发送新请求并等待新回执 | 实际回环 peer 回复手工发送的 receipt；拒绝复用且写入数不变，消费旧回执后新请求与新回执完成。 |
| 应用只等待业务消息时，健康心跳不断积压进有界事件队列 | 由核心更新存活时间；仅交付给当前匹配等待者，不缓存未观察心跳 | 最大队列 1，输入 32 个心跳和一条 MESSAGE；当前心跳等待者收到一个心跳，其他心跳不积压，业务正文完整交付，队列字节和计数归零，会话仍 Active。业务两条超限测试仍要求关闭。 |
| Node 大于定时器范围的延迟会被运行时截成极短延迟 | 拒绝超范围 tickMs/timeout 和非函数 predicate | 参数边界拒绝，未创建等待者；不靠运行时告警或隐式截断。 |

核心 JS/Wasm-GC 各 33 项，运输生命周期与 API 边界 9 项；独立消费者三个场景在两后端 check/build/test/run；401 有效差分用例与 1201 次参考分段解析；离线三场景和 JS 边界。最终全部阶段以交付 verification/ 的原始日志、退出码、工具版本和源码 SHA256 为准。

历史失败：运输字节容量 fixture 在调整心跳语义时曾被现有 message 等待者消费，导致“应超限”的断言失败。修正 fixture 为不匹配该等待者的 receipt，保留原字节容量及抛错断言；业务消息计数超限另用真实 MESSAGE 回环验证。没有削弱容量约束或放宽非法输入。

交付包保留源码、原始完整验证、实际本地 package 候选、消费者源码和依赖解析、中文矩阵、复用审查、Git bundle、来源和 AI_USAGE。只用既有隔离 SDK，检查串行执行；没有 SDK、凭据或个人表单进入源码包。

真实 Artemis 三例和五项补充检查已通过，另确认该版本事务 ACK 不受支持、NACK 丢弃的限制。临时实例停止、端口释放、runtime 清理均有证据。未完成条件仍明确：其他 broker 和支持事务 ACK 的真实互操作。脚本 peer 与参考差分本身仍不能算真实 broker 验证。这里的“本地交付”不宣称比赛验收或生产兼容认证通过。
